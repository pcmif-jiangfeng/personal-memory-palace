# 执行原则

## 1. 只完成当前 Task

你的目标不是一次完成整个项目。

严格限制范围：

- 只实现当前 Task 中明确要求的内容。
- 不提前实现 Future Roadmap。
- 不因为看到未来需求而提前架构扩展。
- 不主动增加未要求的新功能。

如果发现未来功能需要预留接口，可以保持代码结构可扩展，但不要实现未来功能。

---

## 2. 开始前先检查项目

在修改代码之前：

请先分析：

- 当前项目结构；
- 已存在功能；
- 当前技术栈；
- 已完成部分；
- 与当前 Task 的关系。

不要直接重写项目。

---

## 3. 优先最小可行实现

实现时遵循：

```
简单
↓
可靠
↓
可维护
↓
可扩展
```

不要为了追求“最佳架构”：

- 引入不必要依赖；
- 大规模重构；
- 替换已有技术；
- 增加复杂系统。

---

## 4. 自主决策

当产品需求已经明确时：

请自行决定：

- 文件结构；
- 组件命名；
- CSS 实现方式；
- 数据字段细节；
- 内部函数设计；
- 普通技术选择。

不要因为这些细节反复询问。

只有以下情况才需要向我确认：

- 会改变产品核心体验；
- 有多个完全不同的产品方向；
- 会造成不可逆的数据损失；
- 缺少无法推断的信息。

---

开发过程中必须遵守：

- PRODUCT_CORE.md 中定义的产品理念；
