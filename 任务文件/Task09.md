# Task09：Memory 照片沉浸式查看

> 状态：已完成并通过本地测试与腾讯云生产验证。本文保留为阶段需求和验收记录。

## 1. 阶段定位

本阶段只完善 Memory 详情页中的照片查看体验。

用户点击记忆照片后，可以在全屏沉浸式查看器中放大照片，并自由缩放、移动，以便仔细观看记忆中的细节。

本功能应服务于“重新遇见过去”的体验，不将项目变成照片编辑器或图库管理系统。

---

## 2. 本阶段目标

完成一个简单、稳定、同时适用于桌面端和移动端的照片查看器，使用户可以：

1. 从 Memory 详情页打开照片的全屏查看模式。
2. 放大或缩小照片。
3. 在照片放大后自由拖动，查看不同区域。
4. 随时退出查看模式，并回到原来的 Memory 阅读位置。

---

## 3. 实现范围

### 3.1 打开照片查看器

- Memory 详情页的主照片应可点击。
- 点击照片后，在当前页面上方打开全屏深色遮罩层。
- 照片初始状态应完整显示在可视区域内，不裁切、不变形。
- 打开后禁止背景页面滚动。
- 打开查看器不应导致 Memory 页面的文字、编辑状态或滚动位置丢失。

### 3.2 照片缩放

桌面端支持：

- 鼠标滚轮缩放。
- 触控板缩放。
- 双击照片在快速放大和恢复初始大小之间切换。

移动端支持：

- 双指捏合缩放。
- 双击照片在快速放大和恢复初始大小之间切换。

缩放行为要求：

- 最小比例为照片初始适应屏幕的大小。
- 最大缩放比例为初始大小的 5 倍。
- 缩放过程应平滑，不应出现明显跳动或闪烁。
- 缩小到最小比例时，照片自动回到居中位置。

### 3.3 照片移动

- 照片放大后，用户可以使用鼠标或单指拖动照片。
- 拖动时应跟随指针或手指移动，不触发浏览器默认的图片拖拽行为。
- 照片处于初始大小时保持居中，不需要产生无意义的偏移。
- 移动范围应受合理边界限制，避免照片被完全拖离屏幕后无法找回。

### 3.4 退出照片查看器

- 右上角提供始终可见的关闭按钮。
- 桌面端支持按 `Esc` 退出。
- 关闭后恢复背景页面的滚动。
- 每次重新打开时，缩放比例和照片位置都恢复初始状态。
- 退出后保留用户打开查看器前的 Memory 页面位置。

### 3.5 视觉与交互

- 查看器应保持安静、克制的博物馆式视觉，不使用宣宾夺主的工具栏。
- 遮罩层使用深色背景，让注意力集中在照片上。
- 可以提供简洁的当前缩放比例或操作提示，但不得遮挡照片主体。
- 关闭按钮需有清晰的焦点样式和可读的辅助技术标签。
- 用户开启“减少动画”系统设置时，不使用强烈的缩放过渡动画。

---

## 4. 技术与数据边界

- 优先使用当前项目已有的 React、CSS 和浏览器指针事件实现。
- 除非原生实现无法在桌面端和移动端保持稳定，否则不引入新的大型依赖。
- 不修改 Memory 数据库结构。
- 不修改照片上传、优化、备份或恢复方式。
- 查看器继续使用当前已保存的 WebP 照片，不要求重新上传原图。
- 不新增 API，不改变当前记忆访问权限。
- 所有当前能看到 Memory 照片的用户都可使用查看器，但不因此获得新的编辑权限。

## 6. 明确不实现

以下内容不属于 Task09：

- 照片裁切、旋转、滤镜或颜色调整。
- 照片替换、删除或重新上传。
- 在照片上添加标注、文字或画笔。
- AI 修复、超分辨率或画质增强。
- 下载原图或建立原图归档系统。
- 多张照片轮播、幻灯片或上一张/下一张导航。
- 缩略图列表或普通相册式图片管理。
- 修改数据库、访问权限、上传流程或备份机制。
