# C2 邀请接受与邮件自检

日期：2026-10-03。结论：C2 服务/API 完成；C3 双方页面仍未恢复，本地中间版本不部署。

## 实现

- email-invite-acceptance.ts 只读取新 collaboration_invites，验证当前账号、邮箱验证状态、指定邮箱、有效期和宫殿状态；未注册时发出的邀请可在目标注册、验证后接受。
- 接受、成员关系、邀请消耗、业务审计及加入通知入队同一事务；旧授权恢复必须使用新邀请。已接受请求可重试，但已退出/被移除成员不能用已消耗邀请恢复。
- 接受和撤销采用 SQLite 写事务串行化；先撤销则不能加入，先接受则撤销不能代替移除。
- 新 POST /api/invites 只接收 targetEmail，必须明确 museumId；新接受入口只接收 inviteId，用户身份从会话获取，不接收伪造身份或旧 bearer token。馆长 GET 列表有分页和 no-store，协作者不可读取目标邮箱名册。
- 邮件复用现有发送器和受控站点地址；新链接仅是邀请定位符，必须登录、验证邮箱并主动接受。HTML 只包含经过验证的 ID/时间，不包含馆内内容。
- application/collaboration-invites.ts 明确先提交邀请，再执行外部发送，不持有数据库事务等待网络。发送失败返回 delivery=failed 并保留邀请；重试复用原截止时间。delivery=accepted 仅指邮件服务接收，不代表实际收件。
- 复用现有请求频率限制保护发送接口（每账号每分钟 10 次）；不是宫殿数、成员数或加入数的产品限制。
