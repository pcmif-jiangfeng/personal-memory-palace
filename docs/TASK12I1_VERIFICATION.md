# Task12I1 — Museum 照片存储用量

## 完成范围

实现按 Museum 重算 `storageUsedBytes` 的内部维护能力和命令。只更新 `museums.storage_used_bytes`，不更新 Museum 版本、编辑时间或配额，不增加页面、公开接口或上传配额拦截。

统计压缩照片及保留原图的实际文件字节数，而不是照片数量、引用次数或上传前源文件大小。已归档、隐藏、放入回收站的照片，只要文件仍存在就计入；上传和删除队列残留也计入。相同存储键只计算一次。

新 Museum 独立目录内符合照片资产格式的落盘文件，即使数据库登记已丢失，也计入用量。旧 `uploads/owner` / `uploads/demo` 文件仅依照已明确的数据库归属计算，不搬迁文件、不猜测归属。缓存、内置展示图片、数据库、备份、尚未完成原子重命名的临时文件不属于本次 Photo 资产用量，因此这不是服务器磁盘总占用。

缺失的登记文件按实际 0 字节处理，并返回 `missingKeys` 供排查，不删除登记或队列。无法读取文件、链接/目录异常、越界路径、跨馆绑定、冲突归属和未分配的旧路径会中止重算，保留原用量字段。

另外修复旧照片删除入口没有传入 scope 时丢失 `museum_id` 的问题：删除队列始终继承原照片的数据库归属，避免后续统计漏算残留文件。原有权限检查和删除审计逻辑保持不变。

## 使用边界

这是暂停写入后的维护快照，不是持续实时更新的计量服务。数据库事务阻止统计过程中登记记录被并发修改；文件系统不参与 SQLite 事务，运行前必须停止所有向该数据目录写入或清理照片的服务/任务。`--quiesced` 仅是操作者确认，不会自动暂停这些进程。同步文件扫描仅用于维护工具，不放进网站请求路径。

上传、删除后的自动更新及并发配额保护留待 I2；不能直接把上一次重算的数值当作实时配额保证。

```powershell
$env:MEMORY_PALACE_DATASET = "owner"
$env:MEMORY_PALACE_DATA_DIR = "<隔离验证数据目录>"
node --experimental-strip-types scripts/recalculate-storage-usage.ts <museum-id> --quiesced
```

命令仅打开已有数据库，不初始化数据或运行迁移。成功输出 Museum ID、字节数、文件数量与缺失存储键；缺少暂停写入确认时退出且不更新统计。
