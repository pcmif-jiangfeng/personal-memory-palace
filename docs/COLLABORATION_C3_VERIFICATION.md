# C3 邀请管理与接受界面自检

日期：2026-10-03。结论：C3 完成，仅本地；成员业务页面授权由后续 D 恢复。

## 实现

- 重写原 InviteManagement / AcceptInviteForm 为新邮箱邀请模型，移除多次、无限期、使用次数、复制 bearer 链接与读取 URL fragment 的旧表单行为。
- /account/invites?museumId=... 只向当前 active 馆长展示本馆目标邮箱及管理按钮；发起、重发、撤销和重新邀请全部调用新服务。发送失败明确提示邀请已保存，但邮件失败，原截止不延长。
- /account/invites 默认显示当前已验证邮箱收到的邀请，支持 inviteId 定位和每页 20 条；仅投影邀请 ID、宫殿名称/类型、状态/截止，不透传任何名册邮箱或内容。查看不会自动接受。
- 明确显示待接受/已接受/已撤销/已过期；只能主动点击接受 pending 邀请，撤销/过期需要馆长重新邀请；服务器始终再次验证，页面按钮不替代授权。
- 馆长设置页添加管理入口，账号菜单添加收到的邀请入口。旧 /invite#token 页面继续关闭，新邮件指向账号邀请页，不复活旧凭证。
- 邀请数据加载与页面渲染分离，避免重复查询；复用现有表单、按钮、布局样式，针对长邮箱/截止时间增加局部换行规则。

## 审查结论

按 code-review-and-quality 检查服务/页面/按钮一致性、响应检查、角色边界、分页和失败状态；参数化查询、强制当前邮箱、无全局公开名册、无旧 token 接受回退、新发送失败不扩大权限。未发现阻断问题。

frontend-ui-engineering 影响了标签与辅助文本分离、原生按钮键盘操作、错误/空/成功状态以及长文本窄屏换行；沿用产品现有视觉语言，没有新增通用界面框架或依赖。
