# Task12I2 — 上传配额检查

## 结论与范围

新增照片上传前检查本馆容量，按已验证的压缩 WebP 实际字节数计费。恰好达到上限允许，超出上限拒绝；Owner 与 Collaborator 使用同一规则，不允许切换 Museum 或并发上传绕过检查。文字、Memory、Stage、后记编辑不接入容量限制。

配额字段原有默认值仍为 0。**0 表示没有可用上传额度，不是无限制。** 本步不替用户设置容量、不实现管理员身份或额度调整页面，也未部署到线上。

## 实现与数据完整性

新增 migration 21：

- `museums.storage_usage_ready`：默认 0，旧数据不假定已计量。
- `photo_asset_usage`：按存储键记录 Museum、字节数和 `reserved` / `stored` 状态，建立 Museum/state 索引。

容量预留与上传队列登记在同一个 SQLite 写事务中完成：

```text
已记账落盘字节 + 进行中的上传预留字节 + 本次压缩字节 <= 配额
```

不扫描磁盘目录，不在数据库事务内等待文件写入。预留立即对其他连接可见；保存成功后将预留转为已落盘用量，不重复收费。照片提交和成功审计仍维持原来的原子事务。

实际文件保存成功但照片提交/审计/权限重查失败时，照片和成功审计不提交；文件仍有上传日志且占用容量，直到真实清理成功。保存失败也保留预留和恢复日志，避免未知残留文件让下一次上传突破限制。恢复任务清理成功后释放；清理失败不提前释放。

删除照片或恢复删除任务，只有文件清理成功才扣减字节。容量释放、台账删除和队列收尾属于同一个数据库事务，失败可重试且不重复释放。若文件已经移除但数据库收尾失败，仍保守保留计量，恢复重试或维护重算后校正。

I1 重算现在同时重建本馆落盘台账并标记计量就绪。返回字段不变；依然要求暂停全部文件写入/清理者，不得在在线上传中调用。新创建的空馆可标记就绪，但仍遵守原有 0 配额。旧 Owner 归属迁移接管已有文件后标记未就绪，必须先重算。

本步没有清理旧公共目录中无法推断归属的未登记文件。外部脚本直接增删图片或旧代码不经台账上传后，也必须暂停写入并重算，不能把台账当作任意文件系统变化的自动监视器。文件系统与 SQLite 不具备共同事务，恢复日志承担崩溃后的对账；未自动超时释放正在运行的上传。

## 接口和用户提示

- 未计量的旧馆上传返回 `503 STORAGE_USAGE_NOT_READY`，提示联系管理员重算。
- 容量不足返回 `507 STORAGE_QUOTA_EXCEEDED`，详情包含本馆当前用量、上限、预留量、本次压缩字节。
- 现有上传任务面板显示容量不足及当前用量/上限；有进行中预留时明确显示，不混淆为单文件过大。原有未登录、格式和单文件大小错误提示保持。
- 不新增任何管理员页面、公开额度查询或访客入口。错误详情只在原有身份与 Museum 授权通过后返回。

## 部署/人工验收前提（生产尚未执行）

1. 先备份数据库与 images，并在隔离副本验收；执行现有数据库初始化/迁移入口，确认 schema_migrations 中有 21。
2. 暂停全部向该副本写入或清理照片的服务。运行 I1 重算工具，确认本馆 `storage_usage_ready=1`、实际字节数和台账一致。不要只把就绪标记改成 1 来绕过核对。
3. 在隔离副本明确设置用于测试的正数额度；0 的馆应被拒绝上传。本步不提供生产容量默认值或 Admin 调整页面。
4. 恢复隔离服务，分别以 Owner/Collaborator 上传，验证刚好够、超额和并发情况；检查任务面板的当前用量/上限提示。
5. 满额时编辑文字、Memory 和 Stage；删除无引用照片，确认清理后可以继续上传。文件恢复工具运行前仍需暂停其他文件写入者，不能清理正在进行的上传。
6. 完成上述验证及容量配置后，再单独决定是否部署。旧馆未重算、配额仍为 0 时，部署本功能将阻止新增照片，但不影响已有内容阅读和文字编辑。
